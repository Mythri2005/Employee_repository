# Starter review

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It truncates the elapsed time to integer minutes before checking the 10-minute grace period. A punch at 09:40:01 is therefore treated as exactly 10 minutes late and gets no late value. It also has no overnight attendance-day reference. | For a 09:30 shift, compare 09:40:00 (0) with 09:40:01 (10); exercise a post-midnight overnight punch. | Compare elapsed seconds against 600 first, then floor whole elapsed minutes from shift start using the record's attendance day. |
| 2 | `compute_work_hours` | Built-in `round` uses binary floats and ties-to-even, rather than the required decimal half-up rounding. | Use durations whose hour value is exactly halfway between hundredths. | Calculate from integer elapsed seconds with `Decimal` and `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | It anchors every shift end on the attendance date, so overnight shifts end a day too early; it also counts any positive overtime rather than requiring 30 minutes. | Punch out at 06:20 for a 22:00-06:00 shift, and at 18:35 for an 09:30-18:30 shift. | Select the next-day end for overnight shifts and apply the 30-minute threshold before flooring. |
| 4 | Startup / indexes | No indexes enforce unique employee codes or attendance days, and none support the required list and analytics queries. | Start with seeded data, then issue concurrent duplicate creates or punch-ins; inspect query plans. | Create idempotent unique and query-supporting indexes at startup. |
| 5 | `health` | It returns success without checking MongoDB, so the readiness probe passes while the database is down. | Stop MongoDB and call `/health`. | Ping MongoDB and return 503 if it cannot be reached. |
| 6 | `create_employee` | The pre-insert duplicate check is not race-safe without a unique index; the input constraints and equal-shift validation are also missing. `created_at` is naive and returned as a datetime rather than epoch milliseconds. | Send invalid fields; send concurrent identical creates; inspect the response and stored timestamp. | Validate the contract, rely on the unique index and translate duplicate-key errors to 409, store UTC time, and serialize epoch milliseconds. |
| 7 | `list_employees` | `skip` starts after page one, and `total` ignores the department filter. There is no page-size bound or guaranteed ordering. | Request page 1, then page 2; compare a department-filtered total to the full count. | Use `(page - 1) * page_size`, count the filtered query, validate pagination, and sort by `emp_code`. |
| 8 | `punch_in` | A missing employee is dereferenced and becomes a 500. Although milliseconds are divided by 1000, `fromtimestamp` creates a naive host-local datetime; timestamps are not truncated to whole seconds and attendance day is not derived in IST. | Punch an unknown code; run under a non-UTC timezone; test near IST midnight and on an overnight shift. | Return 404 for an unknown employee, convert to aware UTC, truncate seconds, and derive the IST attendance date and shift. |
| 9 | `punch_in` | The caller can submit a non-presence status, and check-then-insert does not prevent concurrent duplicate attendance. | Submit `ABSENT`, then race two requests for the same employee/day. | Restrict the request model to presence statuses and make the unique `(emp_code, date)` index the atomic conflict guard (409). |
| 10 | `punch_in` response | PyMongo adds `_id` to the inserted document; the endpoint converts it to an `id` field, but the contract makes Mongo IDs internal and excludes attendance IDs. | Inspect the JSON response for `id`. | Omit both `_id` and any replacement ID from responses. |
| 11 | `list_attendance` | It reads the entire matching collection into Python and sorts/slices in memory, which will not scale to 100,000 records. Its order is incomplete, output includes an `id`, and pagination is not validated. | Seed a large collection and request a late page; inspect ordering and response keys. | Count the filter separately and perform indexed sorting, skip, and limit in MongoDB; serialize records without identifiers. |
| 12 | `list_attendance` | It accepts a reversed date range instead of returning 422, and has no query parameter validation. | Request `date_from` later than `date_to`, or an unsupported status. | Validate dates/status and reject reversed bounds. |
| 13 | `list_attendance` / serialization | Seeded BSON datetimes, missing default fields, and history timestamps are not converted to the required epoch-millisecond response format. | Read a record with a history entry or omitted optional stored fields. | Normalize all record and nested history times, and fill documented defaults. |
| 14 | Remaining contract | Punch-out, regularization, all four analytics endpoints, and MongoDB explain are absent. | Call each operation described in `openapi.yaml`. | Implemented the endpoints, including atomic updates, audit history, MongoDB aggregation pipelines, and execution-statistics explain. |

**Reviewed and not a defect:** using `emp_code` as the business key and storing calendar dates as `YYYY-MM-DD` strings match the data model. The API should not expose MongoDB `_id`; the starter's `id` aliases were therefore removed rather than retained as a convenience.
